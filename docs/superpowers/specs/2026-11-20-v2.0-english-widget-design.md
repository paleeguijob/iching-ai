# อี้จิง AI 2.0 — ภาษาอังกฤษ + Widget กว้าประจำวัน

20 พ.ย. 2026 · ดึงเฟส 2.4 ของ [สเปก v2](2026-11-07-v2-design.md) ขึ้นมาทำก่อน และปรับให้เข้ากับแอปปัจจุบัน (เซียมซี การ์ดคำทำนาย แคมเปญ โปสเตอร์) ที่สเปกเดิมยังไม่มี

## 1. ทำไม และเป้าหมาย

เจ้าของแอปต้องการให้ **ผู้ใช้ต่างประเทศที่อ่านไทยไม่ได้ใช้แอปได้ครบเหมือนคนไทย** จึงทำภาษาอังกฤษก่อนเฟส 2.1–2.3

- งานนี้ต่อบน branch `feature/v1.4-siamsi` (เซียมซียังไม่ได้ปล่อย) แล้วปล่อยรวมเป็น **2.0.0 · `versionCode` 200** แทน 1.4.0
- **กำหนดส่ง Play: อาทิตย์ 22 พ.ย. 2026** (ถ้าทันส่งเสาร์ 21 พ.ย.) เปิดภาษาอังกฤษตั้งแต่วันแรก
- ปล่อยพร้อมกันในเวอร์ชันเดียว: เซียมซี + ภาษาอังกฤษ + Widget

**เป้าหมาย**
- ทุกหน้าจอ ทุกเนื้อหา (อี้จิง 64 กว้า เซียมซี 160 ใบ แคมเปญปีใหม่) และคำทำนาย AI ใช้ได้เป็นภาษาอังกฤษ
- Widget กว้าประจำวันบน Android
- ภาษาไทยเหมือนเดิมทุกจุด

**ไม่ทำในรอบนี้:** ภาษาจีน (เฟส 2.5), คำทำนายเชิงลึก/สรุปรายเดือน/อาจารย์ (2.1–2.3), iOS widget, เลือกภาษาตามภาษาเครื่อง

**ถือว่าล้มเหลวแม้จะทำงานได้ ถ้า:**
- ผู้ใช้ไทยเห็นอะไรเปลี่ยนไปจากเดิม (ข้อความ ตัวเลขไทย วันที่ พ.ศ.)
- โหมดอังกฤษมีข้อความไทยหลงอยู่ หรือ AI ตอบเป็นภาษาไทย
- คำแปลผิดความหมายจนคำทำนายเพี้ยน หรือคัดลอกคำแปลที่มีลิขสิทธิ์ (เช่น Wilhelm/Baynes)

## 2. ข้อจำกัด

- เวลา 1–2 วัน เจ้าของแอปตรวจคำแปลทั้งหมดไม่ทัน → ต้องมีทางแก้หลังปล่อยโดยไม่ออกแอปใหม่ และปิดภาษาอังกฤษได้ทันที
- ค่าที่ตั้งได้อยู่ใน `config/runtime` ตามแบบ `aiEnabled` / `siamsiEnabled`
- คำแปลทำเองจากต้นฉบับจีน (public domain) และคำอธิบายไทยของทีม
- ผู้ใช้ 1.x ทุกคนใช้ภาษาไทย ต้องอัปเดตแล้วอยู่ภาษาไทยต่อโดยไม่ถูกถาม
- แอปเวอร์ชันเก่าที่ยังไม่อัปเดตต้องทำงานเหมือนเดิม (ไม่ส่ง `lang` → server ใช้ไทย)

## 3. ทางเลือกที่พิจารณา

**เก็บข้อความ UI สองภาษา**

| ทาง | ข้อดี | ข้อเสีย |
|---|---|---|
| A. `strings.xml` ของ Compose Multiplatform (สเปกเดิม) | มาตรฐาน ใช้เครื่องมือนักแปลได้ | สลับภาษาในแอปต้องบังคับ locale + สร้างหน้าจอใหม่ · คำแปลขาดแล้ว build ผ่าน ไทยหลุดมาเงียบ ๆ · widget/notification อ่านคนละทาง |
| **B. `Strings` เป็น Kotlin หนึ่งชุดต่อภาษา ส่งผ่าน CompositionLocal (เลือก)** | สลับทันที · คำแปลขาด = compile ไม่ผ่าน · ViewModel, widget, notification ใช้ชุดเดียวกัน · แปลงโค้ดเร็ว | ไม่ใช่รูปแบบมาตรฐาน ถ้าจ้างนักแปลภายนอกต้อง export |

เจ้าของแอปเลือก **B** เพราะเวลาสั้น และต้องการหน้าเลือกภาษาในแอป

**วันปล่อยกับการตรวจคำแปล** — พิจารณา (1) ส่งวันอาทิตย์แต่ปิดอังกฤษไว้จนตรวจครบ (2) ส่งวันอาทิตย์และเปิดอังกฤษเลย (3) เลื่อน 1–2 สัปดาห์ · เจ้าของแอปเลือก **(2)** โดยมีตัวกันพลาดในหัวข้อ 9

**เนื้อหาอังกฤษ** — แยกไฟล์ใหม่ (เลือก) แทนการเพิ่มฟิลด์ `*En` ในไฟล์ไทย: ไฟล์ไทยไม่ถูกแตะ ตรวจง่าย อัปเดตผ่าน Hosting ทีละไฟล์

## 4. การเลือกภาษา

- `AppSettings.language`: `"th" | "en" | null` เก็บใน DataStore
- **ติดตั้งใหม่:** หน้าแรกสุดก่อน onboarding คือหน้าเลือกภาษา ปุ่ม "ภาษาไทย" และ "English" ไม่เลือกไว้ล่วงหน้า บรรทัดล่าง "เปลี่ยนได้ในตั้งค่า · Change anytime in Settings"
- **อัปเดตจาก 1.x:** ถ้า onboarding เคยผ่านแล้วและ `language == null` → ตั้งเป็น `"th"` เงียบ ๆ ไม่แสดงหน้าเลือก
- **ตั้งค่า:** แถว "ภาษา / Language" (ชื่อแถวเป็นสองภาษาเสมอ) เปิด sub-page เลือก ไทย / English เปลี่ยนแล้วมีผลทันทีทุกหน้า
- `englishEnabled = false` ใน runtime config → ซ่อนหน้าเลือกและแถวตั้งค่า ผู้ใช้ที่เลือกอังกฤษไว้ถูกบังคับเป็นไทยจนกว่าจะเปิดใหม่ (ค่าที่เลือกไว้ยังเก็บไว้)
- Analytics: `language_selected {lang, source: first_launch|settings}` และ user property `app_lang`

## 5. ข้อความ UI

- interface `Strings` ใน `composeApp` commonMain · `ThStrings` (ข้อความเดิมตรงตัว) และ `EnStrings`
- `LocalStrings` เป็น CompositionLocal ที่ root ตาม `AppSettings.language` · โค้ดนอก Compose (ViewModel, `androidApp`) รับ `Strings` จาก DI หรือ provider ตามภาษาปัจจุบัน
- ข้อความที่มีตัวแปรเป็นฟังก์ชัน เช่น `fun quotaLeft(n: Int): String`
- **ตัวเลข:** `formatNumber(n)` ตามภาษา — ไทยใช้ ๐–๙ ตรงที่เดิมใช้ อังกฤษใช้ 0–9 · `toThaiNumerals()` ที่เรียกตรงใน UI เปลี่ยนไปผ่านตัวนี้
- **วันที่:** `ThaiDates.kt` → ตัวจัดรูปตามภาษา ไทย พ.ศ. เหมือนเดิม อังกฤษ ค.ศ. เช่น "20 Nov 2026"
- **ปีนักษัตร** (`campaignYearLabel`): ไทย "ปีมะแม ๒๕๗๐" อังกฤษ "Year of the Goat 2027"
- ชื่อกว้าในโหมดอังกฤษ: อักษรจีน + pinyin + ชื่ออังกฤษสั้นที่ตั้งเองจากความหมายอักษรจีน เช่น "乾 Qián · Heaven", "泰 Tài · Harmony" · *(ผู้เขียนตัดสินเอง)* ไม่ใช้ชุดชื่อของ Wilhelm/Baynes ทั้งชุด ("The Creative", "The Receptive", ...) เพื่อไม่ให้ดูเหมือนยกฉบับนั้นมา ชื่อบางกว้าอาจตรงกันโดยธรรมชาติของความหมาย (เช่น Peace) ได้
- `androidApp/src/main/res/values/strings.xml` (ชื่อแอป ช่องแจ้งเตือน) เพิ่ม `values-en` · ชื่อแอปอังกฤษ "I Ching AI"
- เทสต์เดิมที่อ้างข้อความไทยตรง ๆ ใช้ `ThStrings` และต้องผ่านเหมือนเดิม

## 6. เนื้อหา

| ไฟล์ไทย (ไม่แก้) | ไฟล์อังกฤษใหม่ | ฟิลด์ที่แปล |
|---|---|---|
| `files/hexagrams.json` | `files/hexagrams.en.json` | ชื่อ คำสำคัญ ตัวบท ภาพ คำอธิบาย ทุกเส้น ข้อความประจำวัน ข้อความประจำปี + ธรรมชาติของตรีกราม |
| `files/siamsi/guanyin100.json` | `files/siamsi/guanyin100.en.json` | `name`, `source.note`, `poem_en` (แปลจาก `poem_orig`), `story`, `summary`, `topics.*`, `keywords` |
| `files/siamsi/jiazi60.json` | `files/siamsi/jiazi60.en.json` | เหมือนข้างบน |

- ไฟล์อังกฤษเก็บเฉพาะฟิลด์ที่แปล อ้างด้วย `id` / `number` แอปรวมกับไฟล์ไทยตอนโหลด ฟิลด์ที่ไม่ต้องแปล (`grade_orig`, `level`, เส้นกว้า ฯลฯ) มาจากไฟล์ไทย
- ใบเซียมซีในโหมดอังกฤษแสดงกลอนจีนต้นฉบับ + คำแปลอังกฤษ (แทนคำแปลไทย)
- ไฟล์อังกฤษของเซียมซีใช้กลไกดาวน์โหลดจาก Hosting เดิม (`/content/siamsi/{id}.en.json` + `version` ใน `config/runtime.siamsiSets`) · `hexagrams.en.json` ทำกลไกเดียวกันเพิ่ม (`/content/hexagrams.en.json` + `hexagramsEnVersion`)
- server ต้องได้ไฟล์อังกฤษด้วย (ผ่าน `copy-data` เดิม) เพื่อใส่ตัวบทอังกฤษใน prompt
- เนื้อหาไทยครบ 160 ใบแล้ว (คำว่า "ตัวอย่าง" ที่เหลือใน 60 กะจื๊อใบ 54 คือ "เตรียมตัวอย่างดี" ไม่ใช่ข้อความตัวอย่าง) ข้อ grep ใน checklist v1.4 ให้ค้น "〔ตัวอย่าง〕" แทน
- **ขั้นตอนแปล (Claude แปลและตรวจเอง):** Claude ร่างจากกลอนจีนต้นฉบับ + ฉบับไทย → subagent อีกตัวตรวจทานเทียบความหมายกับต้นฉบับทั้งสอง → เทสต์ว่าทุกกว้า/ทุกใบมีฟิลด์ครบ ไม่มีอักษรไทย และความยาวไม่เกินข้อจำกัดเดิม (ข้อความประจำวัน ≤ 120 ตัวอักษร, ข้อความประจำปีตามขีดใน `docs/content/year-messages.md`)

## 7. Server

- แอปส่ง header `X-App-Lang: th|en` ทุก request · ไม่มีหรือไม่รู้จัก → `th`
- reading และ siamsi reading เก็บ `lang` · ถามต่อใช้ `lang` ของ reading นั้น ไม่ใช่ของ request
- `prompt.ts`, `siamsi.ts`, `summary.ts`: persona, กฎร่วม, กฎสรุป และกฎการ์ดคำทำนาย แยกตามภาษา · ใส่ตัวบทกว้า/ใบเซียมซีจากไฟล์ภาษานั้น · สั่งชัดว่า "ตอบเป็นภาษาอังกฤษเท่านั้น"
- **marker ไม่เปลี่ยน:** `[สรุป]`, `[ดวงเด่น]`, `[ควรระวัง]`, `[คำแนะนำ]` ใช้ตรงตัวทุกภาษา (ผู้ใช้ไม่เห็น ตัวแยกในแอปไม่ต้องแก้) · ชื่อหัวการ์ดที่ผู้ใช้เห็นมาจาก `Strings` (อังกฤษ: "Going well", "Watch out", "What to do")
- persona อังกฤษคงบุคลิกนักพรตเดิม แต่ไม่ใช้คำว่า "อาตมา" — ใช้น้ำเสียงผู้รู้สุภาพ
- ความยาวสรุปภาษาอังกฤษสูงสุด 140 ตัวอักษร
- `safety.ts`: คำวิกฤตภาษาอังกฤษ (self-harm, medical emergency) และข้อความตอบเป็นภาษาอังกฤษ แนะนำบริการฉุกเฉินในพื้นที่และ findahelpline.com · ตรวจทั้งสองชุดคำเสมอไม่ว่าภาษาใด
- push กว้าประจำวัน: topic ใหม่ `daily-hexagram-en` ข้อความจาก `hexagrams.en.json` · push แคมเปญมีฉบับอังกฤษไปที่ topic อังกฤษ · แอป subscribe topic ตามภาษา เปลี่ยนภาษา → unsubscribe topic เดิม
- push แคมเปญ (`PUSH_COPY` ใน `campaign.ts`): *(ผู้เขียนตัดสินเอง)* Claude เขียนฉบับอังกฤษ ใช้คำอวยพรตรุษจีนสากล ("Happy Lunar New Year") แทนคำอวยพรแบบไทย ส่งไป `daily-hexagram-en`
- runtime config ใหม่: `englishEnabled` (ค่าเริ่มต้น `true`), `hexagramsEnVersion`
- **ขอบเขตของ `englishEnabled = false`** *(ผู้เขียนตัดสินเอง)*: server ก็ตรวจด้วย ถือ request ใหม่เป็น `th` แม้แอปส่ง `en` · ถามต่อของ reading อังกฤษเดิมยังตอบอังกฤษ (ตามภาษาของ reading) · แอปที่ถูกบังคับเป็นไทยย้ายไป subscribe topic ไทย · push อังกฤษหยุดส่ง
- โปสเตอร์และ promo: เพิ่มช่องอังกฤษ (`titleEn`, `bodyEn`, `imageEn` ฯลฯ ตามช่องที่มี) ใน `/status` · ไม่มีฉบับอังกฤษ → ไม่แสดงในโหมดอังกฤษ
- error message ที่ server ส่งให้ผู้ใช้เห็น (ถ้ามี) แยกตามภาษา

## 8. ส่วนอื่นในแอป

- **เสียงอ่าน:** ตั้ง TTS เป็น `en-US` ในโหมดอังกฤษ (ตอนนี้ fix เป็น `th-TH`)
- **การ์ดแชร์ / ภาพแชร์:** ข้อความบนการ์ดตามภาษา
- **Paywall:** ราคาและระยะเวลามาจาก Play ตามเดิม ข้อความอังกฤษต้องบอกราคา ระยะเวลา และวิธียกเลิกชัดเจน
- **Notification ในเครื่อง** (ถ้ามี) ใช้ `Strings` ตามภาษาปัจจุบัน
- **บันทึกชะตา:** reading เก่าแสดงในภาษาที่ได้มา ส่วน UI รอบ ๆ ตามภาษาปัจจุบัน
- **ขอรีวิว / feedback / แชร์แอป:** ข้อความตามภาษา

## 9. ตัวกันพลาด (เพราะเปิดอังกฤษก่อนตรวจครบ)

1. `englishEnabled` ปิดได้ทันทีโดยไม่ต้องออกแอปใหม่
2. แก้คำแปลผ่าน Hosting + เพิ่ม version (หัวข้อ 6)
3. **Claude เป็นผู้แปลและผู้ตรวจ** (เจ้าของแอปมอบหมาย 20 พ.ย.): ร่าง → ตรวจทานโดย agent แยกที่ไม่ได้ร่าง เทียบต้นฉบับจีนและไทยทุกกว้าทุกใบ → Claude ไล่ดูบน emulator ทุกหน้าจออังกฤษ และคำทำนายจริง 5 คำถาม · เจ้าของแอปไม่ต้องตรวจก่อนส่ง
5. **ถ้าคำแปลไม่ครบหรือตรวจไม่ผ่านภายในวันส่ง** *(ผู้เขียนตัดสินเอง ยังไม่ได้รับคำยืนยัน)*: ส่งตามกำหนดโดยตั้ง `englishEnabled = false` เมื่อคำแปลเสร็จ อัปไฟล์ขึ้น Hosting แล้วเปิดสวิตช์ · ไม่ปล่อยคำแปลที่ไม่ครบ
4. ทดสอบ prompt อังกฤษด้วยคำถามจริง 20 ข้อก่อนส่ง (ลดจาก 50 ในสเปกเดิมเพราะเวลา): ตอบเป็นอังกฤษ 100%, อ้างกว้าถูก, marker การ์ดครบ, คำถามวิกฤตผ่าน safety ทุกข้อ

## 10. Widget กว้าประจำวัน (Android)

- Jetpack Glance ใน `androidApp` ขนาด 2×2 (สัญลักษณ์กว้า + ชื่อ) และ 4×2 (+ ข้อความประจำวัน)
- สูตรเลือกกว้าเดิม (`dailyHexagramId`, UTC+7) อ่านข้อมูลในแอป ไม่เรียก network ไม่เรียก AI
- ภาษาตาม `AppSettings.language` · เปลี่ยนภาษาแล้ว widget อัปเดตทันที
- อัปเดตตอนเที่ยงคืน UTC+7 ด้วย WorkManager และตอนเปิดแอป
- ธีมสว่าง/มืดตามระบบ ใช้สีแอป (ไม่ใช้ dynamic color)
- แตะแล้วเปิดหน้ากว้าประจำวันของวันนั้น (deep link เดียวกับ push)
- Analytics: `widget_added`, `widget_removed`, `widget_tap`

## 12. การตรวจรับ

- หน้าจอไทยทุกหน้าเหมือนก่อนเปลี่ยน (เทียบ screenshot ก่อน/หลังอย่างน้อย หน้าแรก เสี่ยงทาย คำทำนาย เซียมซี บันทึก ตั้งค่า paywall)
- โหมดอังกฤษบนจอแคบและทุกธีม: ไม่มีอักษรไทยหลง (ยกเว้น marker ภายในที่ไม่แสดง) ไม่มีข้อความถูกตัด
- ติดตั้งใหม่ → เห็นหน้าเลือกภาษา · อัปเดตจาก 1.3 → ไม่เห็น ได้ไทย
- เปลี่ยนภาษาในตั้งค่า → ทุกหน้า widget และ push topic เปลี่ยนตาม
- เทสต์ server: ไม่มี `lang` → ไทย · `lang` ไม่รู้จัก → ไทย · ถามต่อใช้ภาษาของ reading · คำวิกฤตอังกฤษเข้า safety
- เทสต์เนื้อหา: ทุกกว้าและทุกใบมีฟิลด์อังกฤษครบ ไม่มีอักษรไทย ความยาวไม่เกินขีด
- Widget บนเครื่องจริง: วางได้ทั้งสองขนาด ข้ามเที่ยงคืนแล้วเปลี่ยน แตะแล้วเปิดหน้าถูก
- checklist ของ v1.4 เดิมใน `RELEASE.md` ครบ
- `./gradlew` test ทุก module และ `npm test` ฝั่ง functions ผ่าน
