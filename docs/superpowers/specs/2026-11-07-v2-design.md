# อี้จิง AI v2 — คำทำนายเชิงลึก, สรุปชะตารายเดือน, เลือกอาจารย์, ภาษาอังกฤษ/จีน, Widget

7 พ.ย. 2026 · อ้างอิงขอบเขตจาก [Product Spec หัวข้อ 2 (v2)](../../specs/2026-10-31-store-release-product-spec.md)

## 1. เป้าหมายและเงื่อนไขเริ่มงาน

เพิ่มรายได้ต่อผู้ใช้ (ARPU) โดยค่า API ÷ รายได้สุทธิ ยังต่ำกว่า 50%

| KPI | เป้า (3 เดือนหลังเปิดแต่ละเฟส) |
|---|---|
| ARPU ต่อเดือน (รายได้สุทธิ ÷ MAU) | เพิ่มขึ้น ≥ 30% จากก่อนเริ่ม v2 |
| ค่า API ÷ รายได้สุทธิ | < 50% (คงเดิม) |
| ผู้ใช้ที่ใช้เหรียญกับคำทำนายเชิงลึก | ≥ 3% ของ MAU |
| สมาชิก Premium ที่เปิดสรุปรายเดือน | ≥ 40% ของสมาชิกที่มีสิทธิ์ |
| ยอดซื้ออาจารย์ | ≥ 1% ของ MAU |
| MAU จากภาษาอังกฤษ/จีน | ≥ 20% ของ MAU ทั้งหมด |

**เงื่อนไขเริ่มงาน:** MAU ≥ 5,000 และกำไรสุทธิต่อเนื่อง 2 เดือน (Product Spec หัวข้อ 6) เขียนและเตรียมได้ก่อน แต่เปิดใช้งานจริงเมื่อผ่านเกณฑ์

**หลักร่วมทุกเฟส**

- ทุกฟีเจอร์มีสวิตช์ใน `config/runtime` (ค่าเริ่มต้นปิด) ตามแบบ `aiEnabled` เพื่อเปิดทีละเฟสและปิดได้ทันทีโดยไม่ต้องออกเวอร์ชันใหม่
- ทุกฟีเจอร์ที่เรียก AI ใช้ safety filter (`core/safety.ts`) และป้าย "เนื้อหาสร้างโดย AI" ชุดเดิม
- ถ้า `aiEnabled = false` ฟีเจอร์ที่เรียก AI ทั้งหมดซ่อนปุ่ม และ server ตอบ `503 ai_disabled` โดยไม่ตัดเหรียญหรือสิทธิ์
- ราคาทุกสินค้าดึงจาก store ห้าม hardcode ตัวเลขในหน้านี้เป็นราคาตั้งต้นสำหรับ Play Console
- ทุกค่าตัวเลข (ราคาเป็นเหรียญ, สิทธิ์ต่อเดือน, เกณฑ์ขั้นต่ำ) อยู่ใน `RuntimeConfig` ปรับได้โดยไม่ต้อง deploy

**ลำดับเฟส**

| เฟส | ฟีเจอร์ | เหตุผลที่อยู่ลำดับนี้ |
|---|---|---|

| 2.2 | สรุปชะตารายเดือน | เหตุผลให้คงสมาชิก Premium ต้นทุนต่ำ |

## 2. เฟส 2.1 — คำทำนายเชิงลึก

### 2.1.1 ผู้ใช้เห็นอะไร

หลังคำทำนายปกติจบในหน้าคำทำนาย มีการ์ด "คำทำนายเชิงลึก" ใต้คำทำนาย เหนือส่วนถามต่อ

| สถานะ | ข้อความหลัก | ปุ่ม |
|---|---|---|
| Premium ที่ยังมีสิทธิ์เดือนนี้ | วิเคราะห์ตรีกราม กว้าซ่อน และเส้นแปรอย่างละเอียด · เดือนนี้เหลือสิทธิ์ {n} ครั้ง | ขอคำทำนายเชิงลึก |
| มีเหรียญ ≥ 3 | วิเคราะห์ตรีกราม กว้าซ่อน และเส้นแปรอย่างละเอียด | ขอคำทำนายเชิงลึก · ๓ เหรียญ (มีอยู่ {coins}) |
| มีเหรียญ < 3 | วิเคราะห์ตรีกราม กว้าซ่อน และเส้นแปรอย่างละเอียด · ใช้ ๓ เหรียญ | ซื้อเหรียญอี้จิง ๑๐ เหรียญ · {ราคาจาก store} |
| ได้คำทำนายเชิงลึกของกว้านี้แล้ว | ไม่แสดงการ์ด แสดงคำทำนายเชิงลึกแทน | — |
| ปิดฟีเจอร์ (`deepReadingEnabled = false`) หรือ `aiEnabled = false` | ไม่แสดงการ์ด | — |

- ลำดับการใช้สิทธิ์: สิทธิ์ Premium ของเดือน → เหรียญ ผู้ใช้ไม่ต้องเลือก
- กดปุ่มที่ตัดเหรียญแล้วขึ้น dialog ยืนยันหนึ่งครั้ง: "ใช้ ๓ เหรียญเพื่อรับคำทำนายเชิงลึกของกว้านี้" [ใช้เหรียญ] [ยกเลิก] · สิทธิ์ Premium ไม่ต้องยืนยัน
- ซื้อเหรียญสำเร็จจากการ์ดแล้ว การ์ดเปลี่ยนเป็นแถว "มีเหรียญ ≥ 3" ทันที ไม่ต้องเสี่ยงทายใหม่
- ไม่มีปุ่มนี้ในคำทำนายที่เป็นตัวบทล้วน (ตอนไม่ได้คำทำนายจาก AI) เพราะคำทำนายเชิงลึกต่อยอดจากคำทำนายปกติ
- เปิดจาก Journal ได้ ทั้งดูคำทำนายเชิงลึกที่เคยได้ และขอใหม่สำหรับ reading เก่าที่ยังไม่มี (ภายในเงื่อนไขเดียวกัน)

**รูปแบบคำทำนายเชิงลึก** (หัวข้อคงที่ ให้ UI แสดงหัวข้อด้วยสไตล์เดียวกันทุกครั้ง)

1. ภาพรวมของคำถาม
2. ตรีกรามล่าง — เรื่องภายใน / ตัวผู้ถาม
3. ตรีกรามบน — สภาพภายนอก / สิ่งที่มากระทบ
4. กว้าซ่อน — สิ่งที่ซ่อนอยู่ใต้สถานการณ์
5. เส้นแปรทีละเส้น (ข้ามถ้าไม่มีเส้นแปร)
6. กว้าที่แปรไปถึง — ทิศทางของเรื่อง (ข้ามถ้าไม่มีเส้นแปร)
7. คำแนะนำสุดท้าย

ความยาวเป้าหมาย 1,200–1,800 ตัวอักษรไทย (`maxOutputTokens` 2,500) ใช้หัวข้อ `##` ใน markdown แอปแปลงเป็นหัวข้อในหน้าจอ

### 2.1.2 Server

**Endpoint ใหม่:** `POST /readings/{id}/deep` ตอบเป็น stream แบบเดียวกับ `/divine`

| ลำดับ | การทำงาน |
|---|---|
| 1 | โหลด reading ของ uid นี้ ไม่พบ → `404` · ไม่มีคำทำนาย AI → `409 no_base_reading` · มี `deep` แล้ว → ส่งข้อความเดิมกลับ ไม่ตัดอะไร |
| 2 | ตรวจ `deepReadingEnabled` และ `aiEnabled` → ไม่ผ่าน `503` |
| 3 | ใน transaction: ตัดสิทธิ์ Premium ของเดือน (`usage.deepMonth`, `usage.deepUsed`) ถ้ามี ไม่มีก็ตัด `deepReadingCoinCost` เหรียญ ไม่พอ → `402 insufficient_coins` |
| 4 | สร้าง prompt และเรียก `deepModel` |
| 5 | สำเร็จ → บันทึก `deep: { text, model, createdAt, charged: "premium" \| "coins" }` ลงใน reading เดิม |
| 6 | เรียกโมเดลไม่สำเร็จหรือถูก safety filter ตัด → คืนสิ่งที่ตัดไปทั้งหมด ใช้ตรรกะ refund เดียวกับ `/divine` |

- ใช้ `minSecondsBetweenReadings` ร่วมกับ `/divine` เพื่อกันกดรัว
- กดซ้ำระหว่างที่กำลังสร้างอยู่ → ใช้ lock ใน reading (`deepPendingAt`) ถ้า lock อายุไม่เกิน 120 วินาที ตอบ `409 in_progress` ไม่ตัดซ้ำ
- `GET /readings` ส่งฟิลด์ `deep` กลับด้วย เพื่อให้ Journal แสดงได้
- `GET /status` เพิ่ม `deepLeftThisMonth` (Premium) และ `deepCoinCost`

**RuntimeConfig ใหม่**

| ฟิลด์ | ค่าเริ่มต้น | หมายเหตุ |
|---|---|---|
| `deepReadingEnabled` | `false` | สวิตช์เฟส |
| `deepModel` | รุ่น Pro ที่ pin เวอร์ชันแล้ว | ห้ามใช้ alias `-latest` เหมือน `freeModel` · `forceModel` ไม่มีผลกับฟิลด์นี้ |
| `deepReadingCoinCost` | `3` | |
| `premiumDeepPerMonth` | `2` | เริ่มนับใหม่วันที่ 1 ตามเวลา UTC+7 ไม่สะสม |

เพิ่มราคา Pro ใน `PRICES_USD_PER_M` ของ `core/gemini.ts` และ log ต้นทุนต่อครั้งแบบเดียวกับคำทำนายปกติ

**ข้อมูลที่คำนวณในโค้ด ไม่ให้ AI คำนวณเอง** (`core/hexagrams.ts`)

- กว้าซ่อน: ตรีกรามล่าง = เส้นที่ 2–4, ตรีกรามบน = เส้นที่ 3–5 นับจากล่าง ใน `pattern` คือ `pattern.substring(1, 4) + pattern.substring(2, 5)` → ฟังก์ชันใหม่ `nuclearHexagram(h)`
- กว้าที่แปรไปถึงและเส้นแปร ใช้ผลจาก `cast.ts` เดิม
- ตรีกรามบน/ล่างของทั้งสามกว้า ใช้ `TRIGRAMS` เดิม

**Prompt** (`core/prompt.ts` ฟังก์ชันใหม่ `buildDeepPrompt`)

- system instruction = persona ที่ใช้กับ reading นั้น (ดูเฟส 2.3) + กฎคำทำนายเชิงลึก
- user message ใส่: คำถาม, หมวด, ชื่อและตัวบทของกว้าหลัก กว้าซ่อน กว้าที่แปรไปถึง, ตรีกราม 6 ตัวพร้อมธรรมชาติ, ตัวบทของเส้นแปรเท่านั้น, คำทำนายปกติที่ได้ไปแล้ว (ให้ต่อยอด ไม่ขัดแย้ง)
- ไม่ใส่ `SUMMARY_RULE` คำทำนายเชิงลึกไม่ต้องมีสรุปการ์ด
- ใช้ context caching กับ system instruction

### 2.1.5 การตรวจรับ

- เทสต์ `nuclearHexagram` ครบ 64 กว้าเทียบตารางอ้างอิง (เช่น กว้า 1 → 1, กว้า 2 → 2, กว้า 63 → 64, กว้า 64 → 63)
- เทสต์ลำดับการตัดสิทธิ์: Premium มีสิทธิ์ → ไม่ตัดเหรียญ · สิทธิ์หมด → ตัด 3 เหรียญ · เหรียญไม่พอ → `402` และไม่มีอะไรเปลี่ยน
- เทสต์ refund: โมเดลล้มเหลว → เหรียญและสิทธิ์คืนครบ
- เทสต์ idempotency: เรียกซ้ำหลังสำเร็จได้ข้อความเดิมและเหรียญไม่ลด · เรียกซ้อนระหว่างสร้าง → `409 in_progress`
- เทสต์สิทธิ์ Premium เริ่มใหม่วันที่ 1 ตาม UTC+7
- ทดสอบ prompt กับคำถามจริง 30 ข้อ: อ้างอิงกว้าซ่อนและตรีกรามถูก 100% (ค่าที่ส่งเข้าไปตรวจได้), อ่านแล้วไม่ขัดกับคำทำนายปกติ ≥ 95%
- เครื่องจริง: ซื้อเหรียญจากการ์ด → ขอเชิงลึก → เหรียญลด 3 → เปิดจาก Journal แล้วเห็นข้อความเดิม

## 3. เฟส 2.2 — สรุปชะตารายเดือน

### 3.1 ผู้ใช้เห็นอะไร

**ที่ Journal:** แถบด้านบน "สรุปชะตาเดือน{ชื่อเดือนก่อน}"

| สถานะ | ข้อความ | การกด |
|---|---|---|
| Premium, เดือนก่อนมีคำทำนาย ≥ 5, ยังไม่ขอ | สรุปชะตาเดือน{เดือน}พร้อมแล้ว · จาก {n} คำทำนาย | สร้างสรุป → เปิดหน้าสรุป |
| Premium, สร้างแล้ว | สรุปชะตาเดือน{เดือน} | เปิดหน้าสรุป |
| Premium, คำทำนายเดือนก่อน < 5 | ไม่แสดงแถบ | — |
| ผู้ใช้ฟรี, เดือนก่อนมีคำทำนาย ≥ 5 | สรุปชะตาเดือน{เดือน} · สำหรับสมาชิก Premium | เปิดหน้าตัวอย่าง |
| ปิดฟีเจอร์ | ไม่แสดงแถบ | — |

- เดือนอ้างอิงเวลา UTC+7 · สรุปของเดือนก่อนขอได้ตั้งแต่วันที่ 1 จนถึงสิ้นเดือนปัจจุบัน หลังจากนั้นปุ่มหาย แต่สรุปที่สร้างแล้วอยู่ตลอด
- ขอได้เดือนละ 1 ครั้ง ไม่มีปุ่มสร้างใหม่
- ผู้ใช้ฟรีที่ใช้ Journal ได้ `freeJournalDays` วัน ใช้จำนวนคำทำนายจริงในเดือนก่อน (server นับ) ไม่ใช่เฉพาะที่เห็น

**หน้าสรุป** (หัวข้อคงที่)

1. ภาพรวมของเดือน — เรื่องที่ถามบ่อยที่สุด
2. กว้าที่ปรากฏซ้ำ และความหมายร่วม
3. สิ่งที่เกิดขึ้นจริง — จากผลที่ผู้ใช้บันทึก (yes / no / partly) ข้ามถ้าไม่มีการบันทึก
4. บทเรียนของเดือน
5. สิ่งที่ควรระวังในเดือนหน้า

ด้านบนเป็นสถิติที่คำนวณในโค้ด ไม่ผ่าน AI: จำนวนคำทำนาย, หมวดที่ถามบ่อยสุด 3 อันดับ, กว้าที่ได้บ่อยสุด, สัดส่วนผลที่บันทึก มีปุ่มแชร์เป็นการ์ดที่แสดงแค่สถิติกับประโยค "บทเรียนของเดือน" ไม่แสดงคำถาม

**หน้าตัวอย่างสำหรับผู้ใช้ฟรี:** แสดงสถิติจริงของผู้ใช้ (ไม่เรียก AI) และข้อความตัวอย่างที่เบลอไว้ซึ่งเป็นข้อความคงที่ ไม่ใช่ของผู้ใช้ พร้อมปุ่ม Premium

**Push:** วันที่ 1 เวลา 09:00 แจ้งสมาชิก Premium ที่มีสิทธิ์ "สรุปชะตาเดือน{เดือน}ของท่านพร้อมแล้ว" ส่งเฉพาะคนที่เปิดการแจ้งเตือนอยู่แล้ว ใช้ FCM topic `monthly-summary-th` ที่แอป subscribe เมื่อเป็น Premium และ unsubscribe เมื่อหมดสถานะ · แตะแล้วเปิด Journal

### 3.2 Server

**Endpoint ใหม่**

- `GET /summaries/{yyyy-mm}` → สรุปที่สร้างแล้ว หรือ `404`
- `POST /summaries/{yyyy-mm}` → สร้าง ตอบเป็น stream

| ลำดับ | การทำงาน |
|---|---|
| 1 | `{yyyy-mm}` ต้องเป็นเดือนก่อนหน้าเดือนปัจจุบันเท่านั้น → ไม่ใช่ `400 invalid_month` |
| 2 | ไม่ใช่ Premium → `403 premium_required` · ปิดฟีเจอร์ → `503` |
| 3 | มีสรุปแล้ว → ส่งของเดิม |
| 4 | นับ reading ในเดือนนั้น < `monthlySummaryMinReadings` → `409 not_enough_readings` |
| 5 | สร้าง lock `pendingAt` ใน doc สรุป (กันซ้ำแบบเดียวกับเฟส 2.1) แล้วเรียกโมเดล |
| 6 | สำเร็จ → บันทึก `users/{uid}/summaries/{yyyy-mm}`: `text`, `stats`, `readingCount`, `model`, `createdAt` · ล้มเหลว → ลบ lock ให้ขอใหม่ได้ |

**ข้อมูลที่ส่งเข้า prompt ต่อ reading** (ไม่ส่งคำทำนายเต็ม เพื่อคุม token): วันที่, หมวด, คำถาม, ชื่อกว้าหลักและกว้าที่แปรไปถึง, สรุปหนึ่งบรรทัด (`summary`), `outcome`, `outcomeNote` · จำกัด 60 reading ล่าสุดของเดือน · input ~6,000 tokens

**โมเดล:** `premiumModel` (ไม่ใช่ Pro) · output ~1,200 tokens · ต้นทุนราว 0.1–0.2 บาท/สมาชิก/เดือน

**Scheduler ใหม่:** `monthlySummaryPush` ตั้งเวลา `0 9 1 * *` เขต `Asia/Bangkok` ส่ง FCM topic และปิดได้ด้วย `monthlySummaryPushEnabled`

**RuntimeConfig ใหม่:** `monthlySummaryEnabled` (`false`), `monthlySummaryMinReadings` (`5`), `monthlySummaryPushEnabled` (`false`)

**ลบบัญชี / รวมบัญชี:** `DELETE /account` ลบ `summaries` ด้วย · `POST /account/merge` ย้าย `summaries` ไปบัญชีปลายทาง ถ้าเดือนซ้ำให้เก็บของบัญชีปลายทาง

### 3.3 Analytics

`summary_banner_shown` (`state`), `summary_create`, `summary_open`, `summary_share`, `summary_preview_premium_tap`

### 3.4 การตรวจรับ

- เทสต์การคำนวณเดือนตาม UTC+7 ที่ขอบเดือน (23:59 / 00:00 ของวันที่ 1)
- เทสต์เงื่อนไข: เดือนผิด, ไม่ใช่ Premium, reading ไม่ถึงเกณฑ์, ขอซ้ำได้ของเดิม, ล้มเหลวแล้วขอใหม่ได้
- เทสต์สถิติในโค้ดกับชุดข้อมูลตัวอย่าง
- เทสต์ลบบัญชีและรวมบัญชี (emulator)
- ทดสอบ prompt กับข้อมูลจำลอง 10 เดือน: ไม่แต่งเหตุการณ์ที่ไม่มีในข้อมูล 100%, อ้างถึงกว้าที่ปรากฏจริง 100%

## 4. เฟส 2.3 — เลือกอาจารย์

### 4.1 อาจารย์

| id | ชื่อ | น้ำเสียงและมุมตีความ | การได้มา |
|---|---|---|---|
| `hermit` | นักพรต (เดิม) | สงบ ลึก เน้นการปล่อยวางและจังหวะธรรมชาติ | ทุกคน (ค่าเริ่มต้น) |
| `confucian` | เซียนขงจื๊อ | สุภาพ มีหลักการ เน้นหน้าที่ ความสัมพันธ์ และการวางตัว อ้างคำอธิบาย 十翼 | ซื้อขาด หรือ Premium |
| `seer` | แม่หมอ | อบอุ่น ใกล้ชิด เน้นความรัก ความรู้สึก และกำลังใจ | ซื้อขาด หรือ Premium |

**กฎที่ทุก persona ต้องมีเหมือนกัน** (ประกอบจากส่วนกลาง ไม่เขียนซ้ำใน persona แต่ละตัว)

- อ้างอิงกว้าและตัวบทที่ส่งเข้าไปเท่านั้น
- ไม่พูดถึงเทคโนโลยีในเนื้อคำทำนาย แต่ถ้าผู้ใช้ถามตรง ๆ ต้องไม่ปฏิเสธว่าเป็น AI
- กฎ safety, การส่งต่อเรื่องวิกฤต และข้อห้ามเรื่องสุขภาพ กฎหมาย การเงิน คงเดิม
- `SUMMARY_RULE` และรูปแบบคำทำนายเชิงลึกเหมือนกันทุกตัว

**ภาพ:** ไอคอนวงกลมของแต่ละอาจารย์ วาดใหม่ในสไตล์เดียวกับไอคอนแอป ไม่ใช้ภาพบุคคลจริง

### 4.2 ผู้ใช้เห็นอะไร

- **หน้าตั้งค่า → "อาจารย์ของท่าน":** รายการ 3 ตัว แต่ละแถวมีไอคอน ชื่อ คำอธิบายหนึ่งบรรทัด และตัวอย่างคำทำนายสั้นที่เป็นข้อความคงที่ (ไม่เรียก AI) · ตัวที่ยังไม่มีสิทธิ์แสดงปุ่ม `{ราคาจาก store}` และ "หรือใช้ได้ทุกตัวกับ Premium"
- **หน้าเสี่ยงทาย:** ชิปเล็กเหนือปุ่มทำนาย "อาจารย์: {ชื่อ}" กดแล้วเปิด bottom sheet เลือกอาจารย์ (เฉพาะตัวที่มีสิทธิ์ + ทางไปหน้าซื้อ)
- **หน้าคำทำนาย และ Journal:** แสดงไอคอนและชื่ออาจารย์ที่ทำนาย reading นั้น
- **ถามต่อและคำทำนายเชิงลึก:** ใช้อาจารย์ของ reading นั้นเสมอ แม้ผู้ใช้เปลี่ยนอาจารย์ในภายหลัง
- **Premium หมดอายุ:** ถ้าอาจารย์ที่เลือกไว้ไม่ได้ซื้อขาด กลับเป็น `hermit` และแจ้งครั้งเดียว "สมาชิก Premium หมดอายุ อาจารย์ของท่านกลับเป็นนักพรต" · reading เก่ายังแสดงชื่ออาจารย์เดิม

### 4.3 Store และสิทธิ์
