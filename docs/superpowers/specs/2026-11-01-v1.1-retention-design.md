## 2. กวาประจำวัน

**เนื้อหา:** เพิ่มฟิลด์ `dailyMessage` ให้ทั้ง 64 กวาใน `hexagrams.json` ยาวไม่เกิน 120 ตัวอักษร เพื่อให้พอดีกับการแจ้งเตือน
เป็นข้อความชวนสะท้อนคิด ไม่สั่งให้ทำอะไรเรื่องสุขภาพ กฎหมาย หรือการเงิน · Claude ร่าง เจ้าของแอปตรวจก่อนปล่อย

**การเลือกกวา:** ฟังก์ชันเดียวกันทั้งแอปและ server

```
epochDay = วันนับจาก 1970-01-01 ตามเวลา UTC+7
index    = (epochDay * 37 + 11) mod 64   (ผลลบให้บวก 64)
id       = index + 1
```

- สูตรเดิมใน `HomeViewModel` ใช้เขตเวลาของเครื่อง จึงเปลี่ยนเป็น UTC+7 คงที่ เพื่อให้ตรงกับ push และเหมือนกันทุกคน
- ลำดับนี้วนครบ 64 กวาใน 64 วันโดยไม่ซ้ำ
- ย้ายไปไว้ใน `core/domain` และรับวันที่เป็นพารามิเตอร์ เทสต์ฝั่ง Kotlin และ TypeScript ใช้ชุดค่าทดสอบเดียวกันเพื่อกันสูตรคลาดกัน

**หน้าจอ:**
- การ์ดในหน้าแรกแสดง `dailyMessage` แทนตัวบท `image` พร้อมจำนวนวัน streak
- กดการ์ดแล้วเข้าหน้าใหม่ `DailyScreen`: รูปกวา, ชื่อ, ข้อความประจำวัน, คำตัดสิน, ปุ่มแชร์ และลิงก์ไปคัมภีร์
- ใช้งานออฟไลน์ได้ทั้งหมด

## 3. Push 07:00

**Server:** Cloud Function ใหม่ `dailyPush` ตั้งเวลา `0 7 * * *` เขต `Asia/Bangkok` region `asia-southeast1`
- ส่งไป FCM topic `daily-hexagram-th` · ไม่เก็บ token รายคนใน Firestore
- title = ชื่อกวา, body = `dailyMessage`, data = `{type: "daily", hexagramId}`, TTL 12 ชั่วโมง เพื่อไม่ให้ข้อความเก่าไปถึงตอนกลางคืน
- ตรรกะสร้างข้อความอยู่ใน `core/` ทดสอบได้โดยไม่ต้องมี Firebase
- ปิดได้ด้วย `config/runtime.dailyPushEnabled = false` ตามแบบ kill-switch เดิม
- ส่งไม่สำเร็จให้ log แล้วปล่อยผ่าน ไม่ retry เพื่อไม่ให้ผู้ใช้ได้รับซ้ำ

**แอป Android:**
- เพิ่ม `firebase-messaging`, channel `daily`, ไอคอนแจ้งเตือนแบบสีเดียว และ `POST_NOTIFICATIONS`
- ขอสิทธิ์หลังผู้ใช้เปิด `DailyScreen` ครั้งแรก ผ่านหน้าอธิบายก่อนขึ้น dialog ของระบบ · ถามครั้งเดียว ไม่ถามซ้ำถ้าปฏิเสธ
- สวิตช์ในหน้าตั้งค่า เก็บใน `AppSettings.dailyPushEnabled` (ค่าเริ่มต้นปิด)
- ถ้าสิทธิ์ของระบบถูกปิดอยู่ กดสวิตช์แล้วพาไปหน้าตั้งค่าของระบบ
- ถ้า subscribe ไม่สำเร็จเพราะไม่มีเน็ต ให้ลองใหม่ตอนเปิดแอปครั้งถัดไป โดยยึดค่าใน settings เป็นหลัก
- แตะแจ้งเตือนแล้วเปิด `DailyScreen` ของวันที่เปิด (ไม่ใช่กวาของวันที่ส่ง ถ้าเปิดข้ามวัน)
- ลบบัญชีแล้ว unsubscribe

**สัญญา native:** เพิ่ม `NativeNotifications` ใน `NativeBridges` (สถานะสิทธิ์, ขอสิทธิ์, subscribe/unsubscribe)

**iOS:** ต้องใช้ APNs key จาก Apple Developer · รอบนี้ Swift ส่งค่า "ไม่รองรับ" และแอปซ่อนสวิตช์ · บันทึกงานที่เหลือใน `RELEASE.md` หัวข้อ 9

## 4. การ์ดแชร์

- วาดด้วย Compose ขนาด 1080×1920 แล้วแปลงเป็น PNG แสดงตัวอย่างก่อนแชร์
- องค์ประกอบ: พื้นม้วนคัมภีร์, รูปกวา, ชื่อจีนและไทย, ข้อความ, ตราชาด 易, ชื่อแอป
- ใช้ธีมดั้งเดิมเสมอ ไม่เปลี่ยนตามธีมที่ผู้ใช้เลือก เพื่อให้จำแบรนด์ได้
- **จากกวาประจำวัน:** ใช้ `dailyMessage`
- **จากคำทำนาย:** ใช้คำตัดสินของกวา และตัดข้อความ AI ไม่เกิน 200 ตัวอักษรที่ขอบประโยค พร้อมป้าย "เนื้อหาสร้างโดย AI"
- ไม่ใส่คำถามของผู้ใช้ลงในการ์ดและข้อความแชร์
- แนบข้อความพร้อมลิงก์ Play Store ของ `com.iching.ai`
- ไฟล์อยู่ใน cache ของแอป แชร์ผ่าน `FileProvider` · แชร์ไม่สำเร็จแสดงข้อความสั้น ๆ ไม่ทำให้แอปล้ม

## 5. Streak และธีม

**กติกา** (ฟังก์ชันล้วนใน `core/domain`):

| เงื่อนไขตอนเปิด `DailyScreen` | ผล |
|---|---|
| ยังไม่เคยนับ | streak = 1 |
| วันเดียวกับครั้งล่าสุด | ไม่เปลี่ยน |
| วันถัดจากครั้งล่าสุด | streak + 1 |
| ห่างเกิน 1 วัน | streak = 1 |
| วันก่อนครั้งล่าสุด (นาฬิกาเครื่องถูกย้อน) | ไม่เปลี่ยน |

- นับเฉพาะตอนเปิด `DailyScreen` ไม่นับแค่เปิดแอป ตามสเปก "เปิดดูกวาประจำวัน"
- ใช้วันแบบ UTC+7 เดียวกับข้อ 2
- เก็บ `current`, `best`, `lastEpochDay`, `unlockedThemes`, `selectedTheme` ใน DataStore เท่านั้น จึงหายเมื่อลบแอป (ยอมรับได้เพราะเป็นของตกแต่ง)
- ของที่ปลดล็อกแล้วอยู่ถาวร แม้ streak จะขาด

**ธีม:**

| ปลดล็อกที่ | ธีม |
|---|---|
| เริ่มต้น | กระดาษหมึก (ธีมปัจจุบัน) |
| 7 วัน | ไผ่เขียว |
| 30 วัน | อรุณชาด |
| 100 วัน | ราตรีหมึก (โทนมืด) |

- `ZenColors` เปลี่ยนจากค่าคงที่เป็น getter ที่อ่านจาก state ของธีมปัจจุบัน หน้าจอเดิมจึงไม่ต้องแก้
- สีที่เขียนตายตัวใน `ZenTheme` ย้ายเข้า palette · ธีมมืดต้องปรับสีไอคอน status bar ด้วย
- เทสต์ตรวจ contrast ของข้อความหลักบนพื้นหลังทุกธีมให้ ≥ 4.5:1
- เลือกธีมในหน้าตั้งค่า ธีมที่ยังล็อกแสดงจำนวนวันที่ต้องใช้
- ถึงเกณฑ์แล้วแสดงข้อความแจ้งใน `DailyScreen` ครั้งเดียว

**ไม่รวมรอบนี้:** ปลดล็อกเสียง เพราะต้องมีไฟล์เสียงที่ใช้ได้ตามลิขสิทธิ์ (ต่างจากสเปกที่ระบุ "ธีม/เสียง")

## 6. เสียงอ่าน (TTS)

- ปุ่มฟัง/หยุดในหน้าคำทำนาย อ่านเฉพาะคำทำนาย AI
- Free กดแล้วไป paywall · Premium เล่นได้เลย · ไม่มีการเรียก server
- ไม่มีเสียงภาษาไทยในเครื่อง: แจ้งผู้ใช้และพาไปหน้าตั้งค่า TTS ของระบบ
- Android ตัดข้อความเป็นช่วงตามขอบประโยคให้ไม่เกิน `getMaxSpeechInputLength()` และเพิ่ม `<queries>` สำหรับ `TTS_SERVICE`
- ออกจากหน้าหรือแอปไปพื้นหลังแล้วหยุดอ่าน

**ต่างจากแบบที่สรุปในแชต:** TTS และการแชร์ใช้ `expect/actual` แบบเดียวกับ `SoundPlayer` แทนการเพิ่ม `NativeSpeech`
เพราะเป็น API ของระบบ ไม่ใช่ SDK ภายนอก และเขียนฝั่ง iOS ด้วย Kotlin ได้โดยไม่ต้องเพิ่ม Swift · `NativeBridges` ใช้เฉพาะ FCM

## 7. Analytics

ใช้ `NativeAnalytics` เดิม: `daily_view`, `streak_milestone{days}`, `theme_selected{theme}`, `share_card{source}`, `tts_play`, `push_toggle{enabled}`, `push_open`

อัตราแชร์ = `share_card{source=reading}` ÷ จำนวนคำทำนาย · ถ้า event นับคำทำนายยังไม่มี ให้เพิ่มด้วย

## 9. การทดสอบ

**อัตโนมัติ**
- domain: สูตรกวาประจำวัน, กติกา streak ทุกแถวในข้อ 5, เกณฑ์ปลดล็อก, การตัดข้อความการ์ด
- data: `dailyMessage` ครบ 64 กวา, ไม่ว่าง และไม่เกิน 120 ตัวอักษร
- backend: ชุดค่าทดสอบสูตรเดียวกับ Kotlin, เนื้อหา push, kill-switch
- theme: contrast ทุกธีม

**บนเครื่อง Android**
- push ทดสอบจาก Firebase Console ไปที่ topic แล้วแตะเปิด `DailyScreen`
- ปฏิเสธสิทธิ์แล้วเปิดสวิตช์ ต้องพาไปหน้าตั้งค่าระบบ
- แชร์การ์ดไป LINE และ IG Story แล้วภาพไม่ถูกตัด
- เปลี่ยนวันที่เครื่องเพื่อทดสอบ streak และการปลดล็อก
- ฟังเสียงอ่านทั้งแบบมีและไม่มีเสียงภาษาไทย
- เปลี่ยนทุกธีมแล้วไล่ดูทุกหน้า

**ทดสอบไม่ได้ในเครื่องนี้:** push 07:00 จริงต้องรอ deploy ขึ้น Firebase
