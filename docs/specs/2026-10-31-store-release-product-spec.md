# Product Spec — แอปอี้จิง AI (Store Release)

Oct 31, 2026 · @AOF

> ถอดความจาก PDF ต้นฉบับ: [2026-10-31-store-release-product-spec.pdf](2026-10-31-store-release-product-spec.pdf)

แอปคุ้มค่า Gemini API ได้ตั้งแต่ราว 1,000 ผู้ใช้ต่อเดือน ถ้าใช้โมเดล Freemium (ฟรี 1 คำทำนาย/วัน) + Premium 49 บาท/เดือน + โฆษณาแบบดูแลกสิทธิ์ และคุมโควตาฝั่ง server อย่างเข้มงวด สิ่งที่ spec v1.0 ขาดมากที่สุดคือการเก็บเงิน การคุมต้นทุน และข้อกำหนด store — ส่วนแก่น (RAG + Persona) ใช้ต่อได้เกือบทั้งหมด

## 1. วิเคราะห์ spec เดิม (v1.0.0)

spec เดิมแข็งแรงด้าน "แก่นของสินค้า" (RAG + Persona + UI ธีมเซน) แต่ยังขาดทุกอย่างที่แอปบน store ต้องมี: บัญชีผู้ใช้ การเก็บเงิน การคุมต้นทุน API ความปลอดภัย และการทำให้คนกลับมาใช้ซ้ำ

### จุดแข็งที่ควรเก็บไว้

- **RAG อิงคัมภีร์จริง** ลด hallucination และเป็นจุดขายเรื่องความน่าเชื่อถือ
- **Persona นักพรตเต๋า** ชัด มีเอกลักษณ์ แยกตัวจากแอปดูดวงทั่วไป
- **ข้อมูลกว้าเป็น static** ทำให้ Library และหน้าผลกว้าไม่ต้องเรียก AI เลย (ประหยัด)
- **UI Zen Minimalist + palette 4 สี** พร้อมใช้เป็น design system

| Persona ห้ามบอกว่าเป็น AI | ข้อ 3 ของ prompt | ขัดนโยบาย store และกฎหมายหลายประเทศ | Persona ยังพูดแบบนักพรตได้ แต่ UI ต้องระบุว่า "เนื้อหาสร้างโดย AI" |

ข้อสังเกตสำคัญ: กฎ "ห้ามบอกว่าตนเองคือ AI" ควรปรับเป็น "ไม่พูดถึงเทคโนโลยีในเนื้อคำทำนาย" แต่ถ้าผู้ใช้ถามตรง ๆ ต้องไม่ปฏิเสธ และแอปต้องติดป้าย AI-generated ไว้ชัดเจน

## 2. ฟีเจอร์ที่แนะนำ (จัดลำดับตาม release)

หลักการเลือก: ทำเฉพาะสิ่งที่ (1) ทำให้คนกลับมาใช้ซ้ำ (2) มีเหตุผลให้จ่ายเงิน หรือ (3) ไม่เพิ่มต้นทุน API — ฟีเจอร์ที่ไม่เรียก AI เลย (Library, กว้าประจำวันแบบข้อความคงที่) คือเครื่องมือดึงคนที่คุ้มที่สุด

### v1.1 — เพิ่มการกลับมาใช้และการบอกต่อ (1–2 เดือนหลังเปิด)

- **กว้าประจำวัน + Push 07:00** — สุ่มกว้าให้ทุกคนวันละ 1 กว้า ใช้ข้อความที่เขียนไว้ล่วงหน้า 64 ชุด (ต้นทุน API = 0)
- **การ์ดแชร์สวย ๆ** — สร้างภาพสไตล์ม้วนคัมภีร์ + ตราประทับชาด สำหรับ IG Story / LINE / TikTok (ช่องทางการตลาดฟรี)
- **Streak / เส้นทางเต๋า** — นับวันต่อเนื่องที่เปิดดูกว้าประจำวัน ปลดล็อกธีม/เสียง
- **หมวดคำถาม** — การงาน / ความรัก / การเงิน / สุขภาพใจ ช่วยผู้ใช้ใหม่ตั้งคำถามได้ และใช้ปรับ prompt
- **เสียงอ่านคำทำนาย (TTS)** — ใช้ TTS ของเครื่อง (ฟรี) เป็น Premium perk
- **แถบคำชี้แนะคงเหลือบนหน้าแรก** — ให้ผู้ใช้เห็นสิทธิ์ของวันนี้และเหรียญที่เก็บไว้ก่อนกดเสี่ยงทาย (รายละเอียดด้านล่าง)

#### แถบคำชี้แนะคงเหลือบนหน้าแรก

**ปัญหา:** ข้อความ "วันนี้เหลือคำชี้แนะจากนักพรต N ครั้ง" เป็นตัวอักษรเล็กสีจางใต้ปุ่มเริ่มเสี่ยงทาย ผู้ใช้อาจมองข้ามและไม่รู้ว่าเหลือการทำนายเท่าไหร่

**เป้าหมาย:** ผู้ใช้เห็นจำนวนคงเหลือได้ทันทีก่อนกดเสี่ยงทาย โดยไม่ต้องอ่านข้อความเล็ก

**ตำแหน่งและหน้าตา**

- วางแถบเต็มความกว้างเหนือปุ่ม "เริ่มเสี่ยงทาย" แทนข้อความเดิมใต้ปุ่ม
- ใช้พื้นกระดาษ เส้นขอบบาง และมุมโค้งแบบเดียวกับการ์ดกวาประจำวัน
- ซ้ายเป็นคำอธิบาย ขวาเป็นตัวเลขขนาดใหญ่ตามด้วยคำว่า "ครั้ง" ใช้เลขไทยเหมือนส่วนอื่นของหน้าแรก
- แสดงเฉพาะจำนวนคงเหลือ ไม่แสดงแบบ "เหลือ/ทั้งหมด" เพราะจำนวนรวมของแต่ละคนเปลี่ยนได้ตามโฆษณาและเหรียญ
- แถบนี้แสดงข้อมูลอย่างเดียว กดไม่ได้

**ข้อความตามสถานะ**

"สิทธิ์วันนี้" = `readingsLeft - coins` คือสิทธิ์รายวันรวมสิทธิ์จากโฆษณา ซึ่งเริ่มนับใหม่ทุกวัน ส่วน `coins` คือเหรียญที่เก็บไว้ข้ามวัน ห้ามรวมสองจำนวนนี้ไว้หลังคำว่า "วันนี้" ทุกแถวของ Premium ขึ้นต้นคำอธิบายด้วย "Premium · "

| สถานะ | คำอธิบาย | ตัวเลข | ข้อความรอง |
|---|---|---|---|
| สิทธิ์วันนี้ > 0 ไม่มีเหรียญ | วันนี้เหลือคำชี้แนะจากนักพรต | สิทธิ์วันนี้ สีเขียวไผ่ | — |
| สิทธิ์วันนี้ > 0 มีเหรียญ | วันนี้เหลือคำชี้แนะจากนักพรต | สิทธิ์วันนี้ สีเขียวไผ่ | และมีเหรียญอี้จิงอีก `coins` เหรียญ ใช้ได้ทุกวัน ไม่มีวันหมดอายุ |
| สิทธิ์วันนี้ 0 มีเหรียญ | เหรียญอี้จิงใช้ทำนายได้อีก | `coins` สีเขียวไผ่ | ใช้ได้ทุกวัน ไม่มีวันหมดอายุ |
| ผู้ใช้ทั่วไป สิทธิ์วันนี้ 0 ไม่มีเหรียญ และยังดูโฆษณาได้ | ชมโฆษณา รับคำชี้แนะเพิ่มได้อีก | `adsWatchableLeft` สีเขียวไผ่ | กดเริ่มเสี่ยงทายได้เลย แล้วชมโฆษณาในหน้าคำทำนาย |
| ผู้ใช้ทั่วไป สิทธิ์วันนี้ 0 ไม่มีเหรียญ และดูโฆษณาครบแล้ว | วันนี้เหลือคำชี้แนะจากนักพรต | ๐ สีชาด | สมัคร Premium หรือใช้เหรียญอี้จิงเพื่อรับคำชี้แนะต่อ · ยังเสี่ยงทายและอ่านตัวบทได้ |
| Premium สิทธิ์วันนี้ 0 ไม่มีเหรียญ | Premium · วันนี้เหลือคำชี้แนะจากนักพรต | ๐ สีชาด | ยังเสี่ยงทายและอ่านตัวบทได้ |
| ปิด AI ชั่วคราว (`aiEnabled = false`) | นักพรตปลีกวิเวกชั่วคราว — ยังเสี่ยงทายและอ่านตัวบทคัมภีร์ได้ | ไม่แสดง | — |

**ตอนสิทธิ์หมดแต่ยังดูโฆษณาได้:** ไม่แสดง ๐ เพราะผู้ใช้อาจเข้าใจว่าวันนี้ทำนายต่อไม่ได้และไม่ไปดูโฆษณา ให้แสดงจำนวนโฆษณาที่ยังดูได้แทน และบอกว่าปุ่มชมโฆษณาอยู่หลังเสี่ยงทาย ส่วน ๐ สีชาดใช้เฉพาะตอนไม่เหลือทางรับคำชี้แนะเพิ่มจากโฆษณาและไม่มีเหรียญแล้ว

**ขอบเขต**

- ไม่เปลี่ยนการคำนวณโควตาหรือการตัดสิทธิ์ฝั่ง server ส่วนคำเรียกเหรียญนอกหน้าแรกให้เป็นไปตามหัวข้อ "เหรียญอี้จิง" ในส่วนแพ็กเกจราคา
- ไม่เพิ่มปุ่มชมโฆษณาบนหน้าแรก ยังชมจากหน้าคำทำนายตามเดิม
- ปุ่มเริ่มเสี่ยงทายยังกดได้ทุกสถานะ เพราะการเสี่ยงทายและตัวบทคัมภีร์ไม่ใช้โควตา
- ตัวเลขมาจากสถานะบัญชีเดิม จึงเปลี่ยนตามเมื่อโควตาถูกตัดหรือได้สิทธิ์เพิ่ม

**การตรวจรับ:** ตรวจบนหน้าจอจริงครบทุกสถานะในตาราง ทั้งจอแคบและทุกธีม โดยข้อความต้องไม่ถูกตัดและตัวเลขต้องอ่านง่าย

### v2 — เพิ่มรายได้ต่อผู้ใช้ (เมื่อมีผู้ใช้ ≥ 5,000 MAU)

- **สรุปชะตารายเดือน** — AI อ่าน Journal ทั้งเดือนแล้วสรุปบทเรียน (Premium, เรียก AI เดือนละ 1 ครั้ง)
- **คำทำนายเชิงลึก (IAP ต่อครั้ง)** — ใช้โมเดลใหญ่กว่า วิเคราะห์ตรีกรามบน-ล่าง กว้าซ่อน (nuclear hexagram)
- **เลือกอาจารย์** — Persona เพิ่ม (เซียนขงจื๊อ / หมอดูหญิง) ขายแยก
- **ภาษาอังกฤษ/จีน** + Home-screen widget กว้าประจำวัน

## 3. โมเดลรายได้และต้นทุน API

คำทำนาย 1 ครั้งมีต้นทุนราว 0.02–0.09 บาท ดังนั้นสมาชิก Premium เพียง ~2% ของผู้ใช้ก็จ่ายค่า API ของทุกคนได้สบาย ตัวเลขด้านล่างเป็น**ค่าประมาณ** (ราคา Gemini จากความจำ ไม่ได้เช็กออนไลน์, 1 USD ≈ 35 บาท) — ต้องเช็กหน้า pricing ของ Google ก่อนตั้งราคาจริง

### ต้นทุนต่อคำทำนาย

สมมติฐาน: input ~2,000 tokens (system prompt + ข้อมูลกว้า + คำถาม) และ output ~800 tokens (ภาษาไทยกิน token มากกว่าอังกฤษ)

| โมเดล | ราคา input / output (USD ต่อ 1M tokens, ประมาณ) | ต้นทุน/ครั้ง (บาท) | ใช้กับ |
|---|---|---|---|
| Gemini Flash-Lite | 0.10 / 0.40 | ~0.02 | Free tier, ถามต่อ |
| Gemini Flash | 0.30 / 2.50 | ~0.09 | Premium คำทำนายหลัก |
| Gemini Pro | 1.25 / 10.00 | ~0.37 | v2: คำทำนายเชิงลึก (IAP) |

ใช้ **context caching** กับ system prompt และใส่เฉพาะเส้นแปรที่สุ่มได้ (ไม่ใส่ทั้ง 6 เส้น) จะลด input ได้อีก 30–50%

| Premium รายปี | 390 บาท (ประหยัด ~34%) | เหมือนรายเดือน + ทดลองฟรี 7 วัน | ~28 บาท/เดือน |
| เหรียญอี้จิง (IAP ครั้งเดียว) | 29 บาท / 10 เหรียญ | 1 เหรียญ = 1 คำทำนาย Flash สำหรับคนไม่ชอบ subscription | ~25 บาท |

#### เหรียญอี้จิง

**กติกา**

- เหรียญไม่มีวันหมดอายุและเก็บข้ามวันได้ ซื้อ 10 เหรียญก็ทำนายได้ 10 ครั้ง จะใช้วันเดียวหรือหลายวันก็ได้
- ระบบใช้สิทธิ์ตามลำดับ: สิทธิ์รายวัน → สิทธิ์จากโฆษณาของวันนี้ → เหรียญ ผู้ใช้ไม่ต้องกดเลือก เหรียญจึงยังอยู่ครบในวันที่ใช้ไม่เกินสิทธิ์รายวัน
- สิทธิ์รายวันและสิทธิ์จากโฆษณาเริ่มนับใหม่ทุกวัน ไม่สะสม
- ถ้าเรียกโมเดลไม่สำเร็จ คืนเหรียญที่ตัดไป

**ข้อความที่ผู้ใช้เห็น**

| จุด | ข้อความ |
|---|---|
| รายละเอียดสินค้าในหน้าซื้อ | ๑ เหรียญ = ๑ คำทำนายจากนักพรต ไม่มีวันหมดอายุ · ใช้เมื่อสิทธิ์ของวันหมด · มีอยู่ N เหรียญ |
| หลังซื้อสำเร็จ | ได้รับเหรียญแล้ว เก็บไว้ใช้วันไหนก็ได้ ไม่มีวันหมดอายุ |
| หน้าแรก | ตามตารางในหัวข้อแถบคำชี้แนะคงเหลือ |
| การ์ดบัญชีในหน้าตั้งค่า | วันนี้เหลือ {สิทธิ์วันนี้} คำทำนาย · เหรียญ {coins} (ไม่มีวันหมดอายุ) โดย Premium แสดงส่วนเหรียญเมื่อมีเหรียญเท่านั้น และแสดงวันหมดอายุสมาชิกต่อท้ายตามเดิม |

**การตรวจรับ:** มีเทสต์ยืนยันว่าเหรียญคงเดิมเมื่อขึ้นวันใหม่ขณะที่สิทธิ์รายวันเริ่มใหม่ มีเทสต์ข้อความหน้าแรกครบทุกแถวของตาราง และซื้อเหรียญบนเครื่องจริงแล้วเห็นว่าสิทธิ์วันนี้ไม่เปลี่ยน แต่จำนวนเหรียญเพิ่ม 10

#### ข้อเสนอเมื่อสิทธิ์ของวันหมด

**ปัญหา:** ผู้ใช้ทั่วไปที่ชมโฆษณาครบ 2 ครั้งของวันแล้ว เห็นแค่ข้อความว่าครบแล้วกับปุ่ม Premium แบบรอง ไม่มีทางซื้อเหรียญจากจุดนี้ ทั้งที่เป็นจังหวะที่ผู้ใช้อยากได้คำชี้แนะมากที่สุด เพราะเพิ่งเสี่ยงทายและเห็นกว้าอยู่ตรงหน้า

**เป้าหมาย:** เมื่อไม่เหลือทางรับคำชี้แนะฟรีแล้ว เสนอให้ผู้ใช้เลือกระหว่างสมัคร Premium หรือซื้อเหรียญอี้จิง แล้วรับคำชี้แนะสำหรับกว้าที่เพิ่งเสี่ยงได้ทันทีโดยไม่ต้องเสี่ยงทายใหม่

**เงื่อนไขที่แสดง:** ผู้ใช้ทั่วไป สิทธิ์วันนี้ 0 `adsWatchableLeft` 0 และ `coins` 0 ซึ่ง server ตอบ `QUOTA` หลังเสี่ยงทาย ถ้ายังดูโฆษณาได้ ให้เสนอโฆษณาก่อนตามเดิม และถ้ามีเหรียญ ระบบตัดเหรียญเองโดยไม่ถึงจุดนี้

**ที่หน้าคำทำนาย (การ์ดแจ้งเหนือตัวบทคัมภีร์)**

| ส่วน | รายละเอียด |
|---|---|
| ข้อความ | คำชี้แนะจากโฆษณาของวันนี้ครบแล้ว ท่านยังรับคำชี้แนะสำหรับกว้านี้ได้ |
| ปุ่มหลัก | Premium · วันละ ๑๐ คำทำนาย · ทดลองฟรี ๗ วัน → เปิด paywall |
| ปุ่มรอง | เหรียญอี้จิง ๑๐ เหรียญ · {ราคาจาก store} → เปิดหน้าซื้อของ store ทันที ไม่ผ่าน paywall |
| ข้อความเล็กท้ายการ์ด | หรือกลับมาใหม่พรุ่งนี้ สิทธิ์ชมโฆษณาเริ่มนับใหม่ทุกวัน |

- ราคาเหรียญดึงจาก store เสมอ ห้าม hardcode เพราะแต่ละประเทศและสกุลเงินต่างกัน ถ้าโหลดราคาไม่ได้ให้ซ่อนราคาแต่ยังกดปุ่มได้
- ข้อความ "ทดลองฟรี ๗ วัน" แสดงเฉพาะเมื่อ store บอกว่าบัญชีนี้ยังมีสิทธิ์ทดลอง ถ้าไม่มีให้ตัดส่วนนั้นออก
- เป็นการ์ดในหน้า ไม่ใช่ popup ไม่บังตัวบทคัมภีร์ ผู้ใช้เลื่อนอ่านตัวบทต่อได้เลย
- ซื้อสำเร็จแล้วกลับมาหน้าเดิม การ์ดเปลี่ยนเป็นสถานะ "ท่านได้รับสิทธิ์เพิ่มแล้ว" พร้อมปุ่ม "รับคำชี้แนะจากนักพรต" ซึ่งขอคำทำนายของกว้าเดิม ไม่ต้องเสี่ยงทายใหม่
- ยกเลิกการซื้อหรือซื้อไม่สำเร็จ การ์ดคงเดิม ไม่แสดงข้อความตำหนิ

**ที่หน้าแรก:** แถบคำชี้แนะคงเหลือยังกดไม่ได้ตามเดิม แต่เปลี่ยนข้อความรองของแถว "ดูโฆษณาครบแล้ว" เป็น "สมัคร Premium หรือใช้เหรียญอี้จิงเพื่อรับคำชี้แนะต่อ · ยังเสี่ยงทายและอ่านตัวบทได้" ให้ผู้ใช้รู้ล่วงหน้าว่ายังมีทาง

**วัดผล (Analytics):** `quota_upsell_shown`, `quota_upsell_tap` (`option` = `premium` | `coins`), `quota_upsell_purchase` (`option`) ใช้คู่กับ KPI Free → Premium conversion

**ขอบเขต**

- ไม่เปลี่ยนโควตา ลำดับการใช้สิทธิ์ หรือจำนวนโฆษณาต่อวัน
- ไม่แสดงข้อเสนอนี้ตอนยังดูโฆษณาได้ ตอนมีเหรียญ หรือตอนปิด AI ชั่วคราว (`aiEnabled = false`)
- ไม่แสดงข้อเสนอนี้กับสมาชิก Premium ที่ใช้สิทธิ์ของวันครบแล้ว การ์ดของ Premium คงเดิม
- ไม่เพิ่มการแจ้งเตือน push หรือ popup ขายของนอกหน้าคำทำนาย

**การตรวจรับ:** มีเทสต์การ์ดตามตาราง และเทสต์ว่าไม่แสดงเมื่อยังดูโฆษณาได้ มีเหรียญ หรือเป็น Premium ทดสอบบนเครื่องจริงด้วยบัญชีทดสอบ: ใช้สิทธิ์โฆษณาให้ครบ → ซื้อเหรียญจากการ์ด → กดรับคำชี้แนะ → ได้คำทำนายของกว้าเดิมและเหรียญเหลือ 9

สมัคร Apple **App Store Small Business Program** และ Google Play (15% สำหรับรายได้ 1M USD แรก) มิฉะนั้นจะโดนหัก 30%

## 4. สถาปัตยกรรมและการคุมต้นทุน

แนะนำ stack เดียวใน ecosystem ของ Google เพื่อใช้ free tier ให้มากที่สุดและดูแลคนเดียวได้: **Flutter + Firebase (Auth, Firestore, Cloud Functions, App Check, Remote Config, Analytics, Crashlytics, FCM) + Gemini API + RevenueCat + AdMob** — ตัด PostgreSQL และ backend แยกออกจาก MVP

### Flow คำทำนาย (ฝั่ง server)

1. แอปเรียก Cloud Function `divine` พร้อม Firebase ID token + App Check token และคำถาม (≤ 300 ตัวอักษร)
2. ตรวจโควตาวันนี้จาก Firestore (entitlement จาก RevenueCat webhook) — หมดโควตา → คืนผลคัมภีร์ดิบ + เสนอ paywall/โฆษณา
3. สุ่มกว้า**ฝั่ง server** (crypto RNG, ความน่าจะเป็นแบบ 3 เหรียญ) — แอปแค่เล่นแอนิเมชันตามผล กันผู้ใช้ปลอมผล
4. ดึงข้อมูลกว้าหลัก + เส้นแปรที่ได้ + กว้าปลายทาง (เก็บเป็น JSON ใน function เอง ไม่ต้องอ่าน DB)
5. Safety pre-check: คำถามเกี่ยวกับทำร้ายตนเอง/การแพทย์ฉุกเฉิน → ตอบด้วยข้อความคงที่ + สายด่วนสุขภาพจิต 1323
6. เรียก Gemini แบบ streaming (โมเดลตาม tier, `maxOutputTokens` 1,024, temperature 0.7)
7. บันทึกผลลง Journal และตัดโควตา — ถ้า Gemini error ไม่ตัดโควตา

### การคุมต้นทุน (สำคัญที่สุดสำหรับเป้า "แค่จ่ายค่า API ได้")

- **API key อยู่ฝั่ง server เท่านั้น** ห้ามฝังในแอป (หรือใช้ Firebase AI Logic + App Check)
- **ตั้ง Budget alert** ใน Google Cloud Billing ที่ 50/90/100% และ kill-switch ผ่าน Remote Config (สลับทุกคนไป Flash-Lite หรือปิด AI ชั่วคราว)
- **Rate limit ต่อ user และต่อเครื่อง** กันสร้างบัญชี anonymous ใหม่เพื่อฟาร์มโควตาฟรี
- **จำกัดความยาว** คำถาม 300 ตัวอักษร, ถามต่อส่งเฉพาะสรุปบทสนทนา ไม่ส่ง history เต็ม
- **เนื้อหาที่ไม่ต้องใช้ AI ให้เขียนล่วงหน้า** (กว้าประจำวัน, คำอธิบายใน Library) — ใช้ Gemini ช่วยร่างครั้งเดียวแล้วคนตรวจ
- **Log token ต่อคำขอ** เข้า BigQuery/Analytics เพื่อดูต้นทุนจริงต่อผู้ใช้เทียบกับตารางในหัวข้อ 3

### ปรับ Schema `hexagrams`

เพิ่มจากเดิม: `upper_trigram`, `lower_trigram`, `name_en`, `judgment` แยกจาก `image` (คำอธิบายภาพลักษณ์), `keywords[]`, `daily_message` (สำหรับกว้าประจำวัน) และตาราง `readings` (uid, question, category, lines[6], primary_id, relating_id, ai_text, model, tokens_in, tokens_out, outcome_note, created_at)

คำแปลคัมภีร์ต้องเป็น public domain (เช่น จากต้นฉบับจีนโบราณ) หรือแปลเอง — ห้ามคัดลอกคำแปลสมัยใหม่ที่มีลิขสิทธิ์

## 6. Roadmap และ KPI

ทำคนเดียวพาร์ทไทม์ ประมาณ 10 สัปดาห์ถึง store แต่ละเฟสมีเกณฑ์ผ่านก่อนไปต่อ

1. **สัปดาห์ 1–2: เนื้อหา** — เตรียมข้อมูล 64 กว้า / 384 เส้น ภาษาไทย + ทดสอบ prompt กับ 50 คำถามจริง เกณฑ์: คำตอบอ้างอิงกว้าถูก ≥ 95%
2. **สัปดาห์ 3–7: MVP** — ทำฟีเจอร์ตามตาราง MVP + Cloud Function + RevenueCat เกณฑ์: ซื้อ/restore ผ่าน sandbox ทั้ง 2 แพลตฟอร์ม
3. **สัปดาห์ 8–9: Beta** — TestFlight + Play closed testing กับเพื่อน 20–30 คน เกณฑ์: crash-free ≥ 99%, ต้นทุนจริง/คำทำนายไม่เกินค่าในหัวข้อ 3
4. **สัปดาห์ 10: ส่ง review และเปิดตัว** — โพสต์การ์ดคำทำนายลง TikTok / กลุ่มสายมู
5. **เดือน 2–3: v1.1** — กว้าประจำวัน, การ์ดแชร์, streak เกณฑ์ไป v2: MAU ≥ 5,000 และกำไรสุทธิต่อเนื่อง 2 เดือน

| KPI | เป้า 3 เดือนแรก | ทำไมสำคัญ |
|---|---|---|
| ค่า API ÷ รายได้สุทธิ | < 50% | เป้าหมายหลักของโปรเจกต์ |
| Free → Premium conversion | ≥ 2% | ตัวแปรที่กำหนดจุดคุ้มทุน |
| D7 retention | ≥ 15% | บอกว่ากว้าประจำวัน/Journal ได้ผล |
| ต้นทุนเฉลี่ยต่อคำทำนาย | ≤ 0.10 บาท | เตือนถ้า prompt บวม |
| อัตราแชร์การ์ด | ≥ 5% ของคำทำนาย | ช่องทางหาผู้ใช้ใหม่ฟรี |
