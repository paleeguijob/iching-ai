# Product Spec — แอปอี้จิง AI (Store Release)

Oct 31, 2026 · @AOF

> ถอดความจาก PDF ต้นฉบับ: [2026-10-31-store-release-product-spec.pdf](2026-10-31-store-release-product-spec.pdf)

แอปคุ้มค่า Gemini API ได้ตั้งแต่ราว 1,000 ผู้ใช้ต่อเดือน ถ้าใช้โมเดล Freemium (ฟรี 1 คำทำนาย/วัน) + Premium 79 บาท/เดือน + โฆษณาแบบดูแลกสิทธิ์ และคุมโควตาฝั่ง server อย่างเข้มงวด สิ่งที่ spec v1.0 ขาดมากที่สุดคือการเก็บเงิน การคุมต้นทุน และข้อกำหนด store — ส่วนแก่น (RAG + Persona) ใช้ต่อได้เกือบทั้งหมด

## 1. วิเคราะห์ spec เดิม (v1.0.0)

spec เดิมแข็งแรงด้าน "แก่นของสินค้า" (RAG + Persona + UI ธีมเซน) แต่ยังขาดทุกอย่างที่แอปบน store ต้องมี: บัญชีผู้ใช้ การเก็บเงิน การคุมต้นทุน API ความปลอดภัย และการทำให้คนกลับมาใช้ซ้ำ

### จุดแข็งที่ควรเก็บไว้

- **RAG อิงคัมภีร์จริง** ลด hallucination และเป็นจุดขายเรื่องความน่าเชื่อถือ
- **Persona นักพรตเต๋า** ชัด มีเอกลักษณ์ แยกตัวจากแอปดูดวงทั่วไป
- **ข้อมูลกว้าเป็น static** ทำให้ Library และหน้าผลกว้าไม่ต้องเรียก AI เลย (ประหยัด)
- **UI Zen Minimalist + palette 4 สี** พร้อมใช้เป็น design system

### ช่องว่างที่ต้องเติม

| ประเด็น | spec เดิม | ผลกระทบถ้าไม่ทำ | ต้องเพิ่ม |
|---|---|---|---|
| โมเดลรายได้ | ไม่มี | ค่า API จ่ายเองทั้งหมด | Freemium + Subscription + IAP (หัวข้อ 3) |
| คุมต้นทุน API | ไม่มี | ผู้ใช้ฟรีหรือบอทกินโควตาไม่จำกัด | Quota ต่อวัน, rate limit, cache, App Check |
| บัญชีผู้ใช้ | กล่าวถึง User ใน DB เท่านั้น | ซื้อแล้วย้ายเครื่องไม่ได้, Journal หาย | Anonymous auth → ผูก Apple/Google |
| วิธีสุ่ม | "โยนเหรียญ หรือ อัลกอริทึมสุ่ม" | ความน่าจะเป็นผิดจากตำรา | กำหนดชัด: 3 เหรียญ (6/7/8/9 = 1/8, 3/8, 3/8, 1/8) + ตัวเลือกวิธีก้านยารอ (yarrow) |
| ถามต่อ (follow-up) | ไม่มี | ประสบการณ์จบเร็ว ไม่มีเหตุผลให้จ่าย | แชตต่อเนื่อง 3–5 รอบ ต่อการเสี่ยงทาย (ฟีเจอร์ Premium) |
| Schema กว้า | มีกว้าหลักกับเส้นแปร | ไม่มีกว้าที่แปรไปถึง (relating hexagram), ไม่มีภาษาอังกฤษ | เพิ่ม trigram บน/ล่าง, image text, name_en, keywords |
| Safety / ข้อจำกัดความรับผิดชอบ | ไม่มี | ถูก reject จาก store, เสี่ยงคำถามสุขภาพจิต/การเงิน | Disclaimer, safety filter, ตอบแบบส่งต่อเมื่อเป็นเรื่องวิกฤต |
| Persona ห้ามบอกว่าเป็น AI | ข้อ 3 ของ prompt | ขัดนโยบาย store และกฎหมายหลายประเทศ | Persona ยังพูดแบบนักพรตได้ แต่ UI ต้องระบุว่า "เนื้อหาสร้างโดย AI" |
| Analytics / Crash | ไม่มี | วัดผลไม่ได้ว่าอะไรทำเงิน | Firebase Analytics + Crashlytics |
| Localization | ไทยอย่างเดียว | ตลาดเล็ก | v2: อังกฤษ, จีน |

ข้อสังเกตสำคัญ: กฎ "ห้ามบอกว่าตนเองคือ AI" ควรปรับเป็น "ไม่พูดถึงเทคโนโลยีในเนื้อคำทำนาย" แต่ถ้าผู้ใช้ถามตรง ๆ ต้องไม่ปฏิเสธ และแอปต้องติดป้าย AI-generated ไว้ชัดเจน

## 2. ฟีเจอร์ที่แนะนำ (จัดลำดับตาม release)

หลักการเลือก: ทำเฉพาะสิ่งที่ (1) ทำให้คนกลับมาใช้ซ้ำ (2) มีเหตุผลให้จ่ายเงิน หรือ (3) ไม่เพิ่มต้นทุน API — ฟีเจอร์ที่ไม่เรียก AI เลย (Library, กว้าประจำวันแบบข้อความคงที่) คือเครื่องมือดึงคนที่คุ้มที่สุด

### v1.1 — เพิ่มการกลับมาใช้และการบอกต่อ (1–2 เดือนหลังเปิด)

- **กว้าประจำวัน + Push 07:00** — สุ่มกว้าให้ทุกคนวันละ 1 กว้า ใช้ข้อความที่เขียนไว้ล่วงหน้า 64 ชุด (ต้นทุน API = 0)
- **การ์ดแชร์สวย ๆ** — สร้างภาพสไตล์ม้วนคัมภีร์ + ตราประทับชาด สำหรับ IG Story / LINE / TikTok (ช่องทางการตลาดฟรี)
- **Streak / เส้นทางเต๋า** — นับวันต่อเนื่องที่เปิดดูกว้าประจำวัน ปลดล็อกธีม/เสียง
- **หมวดคำถาม** — การงาน / ความรัก / การเงิน / สุขภาพใจ ช่วยผู้ใช้ใหม่ตั้งคำถามได้ และใช้ปรับ prompt
- **เสียงอ่านคำทำนาย (TTS)** — ใช้ TTS ของเครื่อง (ฟรี) เป็น Premium perk

### v2 — เพิ่มรายได้ต่อผู้ใช้ (เมื่อมีผู้ใช้ ≥ 5,000 MAU)

- **สรุปชะตารายเดือน** — AI อ่าน Journal ทั้งเดือนแล้วสรุปบทเรียน (Premium, เรียก AI เดือนละ 1 ครั้ง)
- **คำทำนายเชิงลึก (IAP ต่อครั้ง)** — ใช้โมเดลใหญ่กว่า วิเคราะห์ตรีกรามบน-ล่าง กว้าซ่อน (nuclear hexagram)
- **เลือกอาจารย์** — Persona เพิ่ม (เซียนขงจื๊อ / หมอดูหญิง) ขายแยก
- **ภาษาอังกฤษ/จีน** + Home-screen widget กว้าประจำวัน

## 3. โมเดลรายได้และต้นทุน API

คำทำนาย 1 ครั้งมีต้นทุนราว 0.02–0.09 บาท ดังนั้นสมาชิก Premium เพียง ~2% ของผู้ใช้ก็จ่ายค่า API ของทุกคนได้สบาย ตัวเลขด้านล่างเป็น**ค่าประมาณ** (ราคา Gemini จากความจำ ไม่ได้เช็กออนไลน์, 1 USD ≈ 35 บาท) — ต้องเช็กหน้า pricing ของ Google ก่อนตั้งราคาจริง

### ต้นทุนต่อคำทำนาย

สมมติฐาน: input ~2,000 tokens (system prompt + ข้อมูลกว้า + คำถาม) และ output ~800 tokens (ภาษาไทยกิน token มากกว่าอังกฤษ)

| โมเดล | ราคา input / output (USD ต่อ 1M tokens, ประมาณ) | ต้นทุน/ครั้ง (บาท) | ใช้กับ |
|---|---|---|---|
| Gemini Flash-Lite | 0.10 / 0.40 | ~0.02 | Free tier, ถามต่อ |
| Gemini Flash | 0.30 / 2.50 | ~0.09 | Premium คำทำนายหลัก |
| Gemini Pro | 1.25 / 10.00 | ~0.37 | v2: คำทำนายเชิงลึก (IAP) |

ใช้ **context caching** กับ system prompt และใส่เฉพาะเส้นแปรที่สุ่มได้ (ไม่ใส่ทั้ง 6 เส้น) จะลด input ได้อีก 30–50%

### แพ็กเกจราคา

| แพ็กเกจ | ราคา | สิทธิ์ | รับจริงหลัง store หัก 15% |
|---|---|---|---|
| Free | 0 | 1 คำทำนาย/วัน (Flash-Lite) + ดูโฆษณาแลกเพิ่ม 2 ครั้ง | รายได้โฆษณา |
| Premium รายเดือน | 79 บาท | 10 คำทำนาย/วัน (Flash) + ถามต่อ + Journal ไม่จำกัด + ไม่มีโฆษณา | ~67 บาท |
| Premium รายปี | 590 บาท (ประหยัด ~38%) | เหมือนรายเดือน + ทดลองฟรี 7 วัน | ~42 บาท/เดือน |
| เหรียญอี้จิง (IAP ครั้งเดียว) | 35 บาท / 10 เหรียญ | 1 เหรียญ = 1 คำทำนาย Flash สำหรับคนไม่ชอบ subscription | ~30 บาท |

สมัคร Apple **App Store Small Business Program** และ Google Play (15% สำหรับรายได้ 1M USD แรก) มิฉะนั้นจะโดนหัก 30%

### จุดคุ้มทุน (ต่อเดือน, ประมาณ)

| รายการ | 1,000 MAU | 5,000 MAU |
|---|---|---|
| ผู้ใช้ฟรี (เฉลี่ย 15 คำทำนาย/เดือน × 0.02 บาท) | ~300 บาท | ~1,500 บาท |
| สมาชิก 2% (เฉลี่ย 120 คำทำนาย+ถามต่อ/เดือน × 0.09 บาท) | ~220 บาท | ~1,100 บาท |
| Apple Developer 99 USD/ปี + backend (Firebase/Cloud Run) | ~500 บาท | ~800 บาท |
| **ต้นทุนรวม** | **~1,000 บาท** | **~3,400 บาท** |
| รายได้ subscription (2% × ~60 บาท เฉลี่ยหลังหัก) | ~1,200 บาท | ~6,000 บาท |
| รายได้ rewarded ads (ประมาณ eCPM ไทย) | ~200 บาท | ~1,000 บาท |
| **สุทธิ** | **~+400 บาท** | **~+3,600 บาท** |

สรุป: คุ้มทุนที่ราว 800–1,000 MAU ถ้า conversion ได้ 2% ตัวแปรที่สำคัญที่สุดคือโควตาฟรี — อย่าให้ฟรีเกิน 1 ครั้ง/วัน (ซึ่งตรงกับปรัชญาอี้จิงที่ไม่ควรถามเรื่องเดิมซ้ำ ๆ อยู่แล้ว)

## 4. สถาปัตยกรรมและการคุมต้นทุน

แนะนำ stack เดียวใน ecosystem ของ Google เพื่อใช้ free tier ให้มากที่สุดและดูแลคนเดียวได้: **Flutter + Firebase (Auth, Firestore, Cloud Functions, App Check, Remote Config, Analytics, Crashlytics, FCM) + Gemini API + RevenueCat + AdMob** — ตัด PostgreSQL และ backend แยกออกจาก MVP

### Flow คำทำนาย (ฝั่ง server)

1. แอปเรียก Cloud Function `divine` พร้อม Firebase ID token + App Check token และคำถาม (≤ 300 ตัวอักษร)
2. ตรวจโควตาวันนี้จาก Firestore (entitlement จาก RevenueCat webhook) — หมดโควตา → คืนผลคัมภีร์ดิบ + เสนอ paywall/โฆษณา
3. สุ่มกว้า**ฝั่ง server** (crypto RNG, ความน่าจะเป็นแบบ 3 เหรียญ) — แอปแค่เล่นแอนิเมชันตามผล กันผู้ใช้ปลอมผล
4. ดึงข้อมูลกว้าหลัก + เส้นแปรที่ได้ + กว้าปลายทาง (เก็บเป็น JSON ใน function เอง ไม่ต้องอ่าน DB)
5. Safety pre-check: คำถามเกี่ยวกับทำร้ายตนเอง/การแพทย์ฉุกเฉิน → ตอบด้วยข้อความคงที่ + สายด่วนสุขภาพจิต 1323
6. เรียก Gemini แบบ streaming (โมเดลตาม tier, `maxOutputTokens` 1,024, temperature 0.7)
7. บันทึกผลลง Journal และตัดโควตา — ถ้า Gemini error ไม่ตัดโควตา

### การคุมต้นทุน (สำคัญที่สุดสำหรับเป้า "แค่จ่ายค่า API ได้")

- **API key อยู่ฝั่ง server เท่านั้น** ห้ามฝังในแอป (หรือใช้ Firebase AI Logic + App Check)
- **ตั้ง Budget alert** ใน Google Cloud Billing ที่ 50/90/100% และ kill-switch ผ่าน Remote Config (สลับทุกคนไป Flash-Lite หรือปิด AI ชั่วคราว)
- **Rate limit ต่อ user และต่อเครื่อง** กันสร้างบัญชี anonymous ใหม่เพื่อฟาร์มโควตาฟรี
- **จำกัดความยาว** คำถาม 300 ตัวอักษร, ถามต่อส่งเฉพาะสรุปบทสนทนา ไม่ส่ง history เต็ม
- **เนื้อหาที่ไม่ต้องใช้ AI ให้เขียนล่วงหน้า** (กว้าประจำวัน, คำอธิบายใน Library) — ใช้ Gemini ช่วยร่างครั้งเดียวแล้วคนตรวจ
- **Log token ต่อคำขอ** เข้า BigQuery/Analytics เพื่อดูต้นทุนจริงต่อผู้ใช้เทียบกับตารางในหัวข้อ 3

### ปรับ Schema `hexagrams`

เพิ่มจากเดิม: `upper_trigram`, `lower_trigram`, `name_en`, `judgment` แยกจาก `image` (คำอธิบายภาพลักษณ์), `keywords[]`, `daily_message` (สำหรับกว้าประจำวัน) และตาราง `readings` (uid, question, category, lines[6], primary_id, relating_id, ai_text, model, tokens_in, tokens_out, outcome_note, created_at)

คำแปลคัมภีร์ต้องเป็น public domain (เช่น จากต้นฉบับจีนโบราณ) หรือแปลเอง — ห้ามคัดลอกคำแปลสมัยใหม่ที่มีลิขสิทธิ์

## 5. ข้อกำหนด App Store / Play Store

แอปหมวดดูดวงเสี่ยงถูก Apple ปฏิเสธด้วยเหตุผล "แอปซ้ำซาก / spam" (Guideline 4.3) จุดต่างที่ต้องโชว์ใน review notes คือ RAG คัมภีร์จริง + Journal + Library — ไม่ใช่แค่สุ่มข้อความ

- [ ] หน้า Privacy Policy + Terms (โฮสต์บน Firebase Hosting) ระบุว่าส่งคำถามไปประมวลผลที่ Google Gemini และสอดคล้อง PDPA
- [ ] ปุ่ม **ลบบัญชีในแอป** (บังคับทั้ง Apple และ Google เมื่อมีการสร้างบัญชี)
- [ ] Sign in with Apple ถ้ามี Google Sign-In บน iOS
- [ ] ปุ่ม Restore Purchases, ลิงก์จัดการ subscription, แสดงราคา + รอบต่ออายุชัดเจนบน paywall
- [ ] ป้าย "เพื่อความบันเทิงและการสะท้อนคิด ไม่ใช่คำแนะนำทางการแพทย์ กฎหมาย หรือการเงิน" + "เนื้อหาสร้างโดย AI"
- [ ] ปุ่มรายงานคำตอบไม่เหมาะสม (Google Play กำหนดสำหรับแอป Generative AI)
- [ ] Age rating 12+ (iOS) / Teen (Play), กรอก Data Safety / Privacy Nutrition Label ให้ตรงกับ Firebase + AdMob
- [ ] ATT prompt (iOS) ก่อนโหลดโฆษณา personalized

## 6. Roadmap และ KPI

ทำคนเดียวพาร์ทไทม์ ประมาณ 10 สัปดาห์ถึง store แต่ละเฟสมีเกณฑ์ผ่านก่อนไปต่อ

1. **สัปดาห์ 1–2: เนื้อหา** — เตรียมข้อมูล 64 กว้า / 384 เส้น ภาษาไทย + ทดสอบ prompt กับ 50 คำถามจริง เกณฑ์: คำตอบอ้างอิงกว้าถูก ≥ 95%
2. **สัปดาห์ 3–7: MVP** — ทำฟีเจอร์ตามตาราง MVP + Cloud Function + RevenueCat เกณฑ์: ซื้อ/restore ผ่าน sandbox ทั้ง 2 แพลตฟอร์ม
3. **สัปดาห์ 8–9: Beta** — TestFlight + Play closed testing กับเพื่อน 20–30 คน เกณฑ์: crash-free ≥ 99%, ต้นทุนจริง/คำทำนายไม่เกินค่าในหัวข้อ 3
4. **สัปดาห์ 10: ส่ง review และเปิดตัว** — โพสต์การ์ดคำทำนายลง TikTok / กลุ่มสายมู
5. **เดือน 2–3: v1.1** — กว้าประจำวัน, การ์ดแชร์, streak เกณฑ์ไป v2: MAU ≥ 5,000 และกำไรสุทธิต่อเนื่อง 2 เดือน

| KPI | เป้า 3 เดือนแรก | ทำไมสำคัญ |
|---|---|---|
| ค่า API ÷ รายได้สุทธิ | < 50% | เป้าหมายหลักของโปรเจกต์ |
| Free → Premium conversion | ≥ 2% | ตัวแปรที่กำหนดจุดคุ้มทุน |
| D7 retention | ≥ 15% | บอกว่ากว้าประจำวัน/Journal ได้ผล |
| ต้นทุนเฉลี่ยต่อคำทำนาย | ≤ 0.10 บาท | เตือนถ้า prompt บวม |
| อัตราแชร์การ์ด | ≥ 5% ของคำทำนาย | ช่องทางหาผู้ใช้ใหม่ฟรี |
